## 1. 背景与目标

### 1.1 背景

高驰（COROS）已发布官方 MCP 服务（`coroslab/COROS-MCP`），把设备、运动、健康、训练计划等个人数据以 MCP 工具形式开放。DSH Desktop 用户若想使用这些能力，当前必须手工完成：找到 MCP endpoint → 理解鉴权方式 → 自行完成 OAuth 授权 → 在 profile patch 里写配置 → 重启。这条路径对非开发者不可行。

### 1.2 产品目标

**把「配置 MCP + 登录高驰账号」这件事，变成「装完插件点一下就可用」。**

一句话定义：安装插件即完成 MCP 对接，点开侧栏「高驰运动」入口即可在插件内完成登录，登录后直接看到自己绑定的设备和最近的运动/健康数据。

### 1.3 成功判据（非量化，先立结构）

首版成立的最小证据链为一条四步闭环：

> **装插件 → 点侧栏入口 → 在插件窗口内完成登录 → 看到设备列表 + 最近 7 天运动**

四步中任一步断裂，本次需求即不成立。

### 1.4 明确不做（首版范围之外）

- 零跳转登录（若影响平台能力边界，见 §7 决策 1）→ 以 S-1 spike 判定
- 服务端登出/吊销（DSH 平台无此能力）
- 登录中途刷新恢复（DSH 平台限制）
- 写入类操作（改高驰账号数据）
- 后台常驻同步与推送
- 多账号、离线缓存、图表趋势

## 2. 目标用户与场景

### 2.1 目标用户

| 用户群 | 覆盖情况 | 依据 |
|---|---|---|
| 有 COROS 设备 + 使用 DSH Desktop 的自用型/开发者用户 | **主目标，闭环可行** | 需求原文 + 环境事实 |
| 用手机号/微信在 COROS App 注册、无邮箱密码 | **结构性阻断，无法闭环** | 高驰授权页仅有「邮箱 + 密码」表单，全页无扫码、无短信验证码、无微信/Apple 登录（已逐词核对 i18n 资源） |
| 忘记密码的用户 | **结构性阻断**（被踢回 App 重置） | 页面「忘记密码」仅弹 `alert`：「Please reset your password on the COROS app login page.」 |
| 非中国大陆地区用户 | 可用，但需处理地区/跨地区弹窗 | 授权页自带 `This integration is not available in your region` 与 `data-region` 属性；CN/EU/US 三区域端点均可达 |
| 装了插件但无 COROS 设备 | 需空态设计 | 假设，未验证 |

> **需求原文措辞需修正**：「点进入口即可在内部完成登录闭环」对上述「结构性阻断用户群」**永远不成立**。建议改写为：**「对已有高驰邮箱账号的用户，在插件内完成登录闭环；其余用户给出明确出口指引。」**

### 2.2 核心用户旅程

| # | 用户步骤 | 期望的可见反馈 |
|---|---|---|
| S0 | 安装插件 → 重启 DSH | 左侧出现「高驰运动」入口 |
| S1 | 点击入口 | 打开高驰运动面板；未登录则显示登录引导 |
| S2 | 点「登录」 | 面板内出现高驰授权页，可输入账号密码并提交 |
| S3 | 授权完成 | 自动回跳，面板无需刷新即变为「已连接」 |
| S4 | 查看设备 | 显示绑定设备的名称/型号 |
| S5 | 查看运动/健康 | 近 7 天概览 + 最近一次运动详情 |
| S6 | 一周后回来 | 仍是已登录态（令牌静默刷新），并显示「上次同步时间」 |

## 3. 原始需求与拆解

原始需求四条：

| # | 原文 | 拆解后 |
|---|---|---|
| R1 | 安装插件后，桌面端左侧上方功能栏出现「高驰运动」入口 | F1 插件可加载 + 侧栏入口 + F2 主页面容器 |
| R2 | 点击入口校验是否完成登录，未完成则需登录 | F3 登录态机 + F4 令牌刷新 + F5 登录闭环 + F6 失败出口 |
| R3 | 登录完成后展示绑定设备列表 + 用户运动/健康信息 | F8 设备列表 + F9 运动记录 + F12 健康总览 |
| R4 | **安装插件即对接高驰 MCP，点进入口即可在内部完成登录** | F5（硬约束）+ F10（未登录不影响入口）+ F17（工具暴露给模型） |

> **术语澄清**：原文「点击入口教研cli是否完成登录」中的「教研cli」按「校验」理解（疑为输入误写）。若另有含义（例如「教研 CLI」指某个命令行工具），需需求方纠正后重开评审。

## 4. 首版范围决策

档位定义：
- **必须做**＝缺了首版就没有交付物，不通过即不可发布
- **建议做**＝边际成本低、明显抬升价值，做不完**不阻塞**首发
- **可暂缓**＝有价值但与首版风险/成本不匹配，进入 V2+

### 4.1 范围总表

| # | 功能项 | 档位 | 理由 | 不做的后果 | 验收信号 |
|---|---|---|---|---|---|
| **F1** | 侧栏「高驰运动」入口（`sidebar.panellist` 的 `id` + `main` keyed slot 配对） | **必须** | 可发现性＝全部价值的入口；槽位写法在 `dsh-context` 有完整实证可抄 | 需求 1 直接不成立 | 安装+重启后出现入口，≤2 次点击进面板；折叠态 56px 轨道下图标可用，控制台无 `slot entry crashed` |
| **F2** | 插件主页面容器（未登录/已登录两态） | **必须** | 承载一切后续功能；`main` 是 keyed slot，必须与 F1 同 id | 无产品 | 点入口切页成功，无 slot crash |
| **F3** | 登录态机：未登录 / 已登录有效 / 已过期可静默刷新 / 刷新失败需重登 + 冷启动恢复 | **必须** | 过期是**本机实测常态**：本机缓存令牌 `expires_at_epoch` 对应 2026-09-08，评审时已过期约 52 天无人刷新（只有 CLI 会刷） | 第二次使用即流失，核心诉求自我否定 | 篡改本地令牌后重开，界面明确提示「需重新登录」，不白屏不转圈 |
| **F4** | 令牌自动刷新（access 30 天 / refresh 180 天，且**轮换**） | **必须** | 官方 FAQ Q11 明确；轮换意味着并发刷新会互相作废，必须单飞（single-flight） | 每月一次「莫名其妙掉登录」 | 手动置过期后自动续期成功，用户无感 |
| **F5** | **插件内登录闭环**（iframe 授权页 + loopback 回调；见 §5） | **必须（待 S-1 判定）** | 唯一差异化。否则用户直接在 Claude/ChatGPT 里加 COROS 连接器即可，插件无存在理由 | 退化成「又一个只读仪表盘」，与高驰 App 竞争且输 | 全程不出现外部浏览器窗口；授权后 ≤5s 自动切「已连接」，**无需复制粘贴任何内容** |
| **F6** | 登录失败的可读出口（密码错 / 无邮箱账号 / 忘记密码 / 地区不支持） | **必须** | 存在结构性阻断用户群，必须给出口指引而非死循环 | 用户卡死在表单里反复试 | 故意输错密码与点「忘记密码」，均出现**中文可执行下一步**（复制链接 / 去 App 重置 / 切换区域） |
| **F7** | 错误分态 + 重试（断网 / 401 / 超时 / 5xx / 未授权历史数据） | **必须** | 首版最高频故障是「连不上」，无分态既无法验收也无法支持 | 白屏或静默失败，用户直接卸载 | 每种失败有可区分文案 + 重试按钮 |
| **F8** | **设备列表**（`queryDevices`） | **必须** | 零入参、成本最低、诊断价值最高——它是「授权真生效」的第一证据 | 首版无任何「高驰」实感 | 首屏出现 ≥1 台设备名称+型号；无设备时显示「未绑定设备」而非空白 |
| **F9** | **近 7 天运动概览 + 最近一次运动详情**（`querySportRecords` + `getActivityDetail`） | **必须** | 官方把「查最近 7 天运动记录」写成接入后的**首个示例指令**，即官方认定的高频场景 | 用户看完设备型号无处可去，价值不成立 | 展示 ≤N 条记录（日期/类型/距离/时长）；0 条时明确空态；**前端必须补齐 10 个必填参数默认值**，不得因缺参报错 |
| **F10** | 未登录状态**不影响入口存在**（不依赖 MCP 首次连接成功） | **必须** | `templates/mcp/cordis.patch.yml` 默认 `failOnStartupError: true`，而 `apply()` 首连失败会 throw → 「未登录」这一必然初始态可能导致**整个 bundle 加载失败、连入口都不出现** | 装了插件看不到入口，最致命 | 未登录状态下入口仍在、页面可打开、错误可读 |
| **F11** | 空/少/错三态设计（未勾历史授权 / 天粒度数据 / 无设备无记录） | **必须** | 三种情况首版必撞：24h 历史授权是**可选勾选**；健康数据是**天粒度**；新用户必然无记录 | 首登即挫败 | 未勾历史授权的账号首登不报错，显式提示「未授权历史数据」 |
| **F12** | 每日健康总览（`queryDailyHealthData` + `queryRecoveryStatus`） | 建议 | 同鉴权同分页，边际成本低；但字段/单位/时区需先取真实返回 | 价值略薄，不影响闭环成立 | 展示 ≥1 项指标 + **数据日期** + 单位，且与 MCP 原始返回一致 |
| **F13** | 「上次同步时间」+ 手动刷新按钮 | 建议 | 天粒度数据下，「没更新」的错觉是必然投诉点 | 用户反复重开插件 | 点击后 3s 内状态可见变化 |
| **F14** | 区域兜底（CN / EU / US 手动切换） | 建议 | 官方 FAQ Q4 **自认**「部分平台不支持域名重定向导致 URL 无效」并给区域独立地址；授权页自带地区弹窗 | 一批非 CN 用户「连接失败」且无法自救 | 默认全局地址失败时可切区域并成功连接 |
| **F15** | 退出登录 / 切换账号 | 建议 | `credentials.deleteRecord` 即可；但**文案不得承诺「已使服务端失效」**（平台无吊销） | 换号无解、售后成本高 | 登出回未登录态，重启后仍为未登录 |
| **F16** | 设置页卡片（endpoint / 传输方式 / 超时 / 区域） | 建议 | 生态惯例（connect-* 系列插件全部用 `settings.section`），排障必需 | 无法自助排障 | 设置页可见可改，重载后生效 |
| **F17** | **把 COROS 工具以 `coros_*` 暴露给模型** | 建议（**第二里程碑**） | 若不对模型开放，「对接 MCP」只剩一张只读报表，放弃大部分想象空间。但与 F10 的 `failOnStartupError` 风险耦合，同时做会放大首发风险 | 插件被压成仪表盘 | 对话中「查最近 7 天跑步」，模型调工具并返回与高驰 App 一致的数据 |

| **F19** | 健康全景（睡眠分期明细、HRV 明细、训练负荷、体能评估、压力时序） | 暂缓 | 工具已具备（`queryTrainingLoadAssessment`/`queryFitnessAssessmentOverview`/`querySleepHrv`/`queryStressTimeSeries` 等），但呈现口径需 UX 先定，且依赖 F12 稳定 | 无 | 见 §9 |

## 5. 登录闭环方案

### 5.1 为什么这是唯一的生死判定点

三条高层要求中，入口（R1）与数据展示（R3）都是可替代的常规 UI 工作。只有「点进入口即可在内部完成登录」是差异化所在，也只它可能做不成。若登录闭环不成立，用户完全可以绕过本插件，直接在模型客户端里挂 COROS 连接器。

### 5.2 路径阶梯

| 路径 | 用户体验 | 实现成本 | 支撑证据 | 阻塞风险 |
|---|---|---|---|---|
| **L1 iframe 嵌入授权页 + loopback 回调**（主路径） | 点登录 → **窗口内**出现高驰登录表单 → 提交 → 自动回跳变已登录 | M | 授权页 `https://opencn.coros.com/oauth2/authorize` 返回 **200，`x-frame-options`/`content-security-policy`/`referrer-policy` 全为 null，`getSetCookie()` 返回 `[]`**；`frame-loopback.html` 已验证 https 页面内嵌 http loopback iframe + `postMessage` 通路可用 | ①宿主页面 CSP `frame-src` 是否放行第三方 iframe（**未验证**）；②用户在窗口内输入高驰密码的信任成本（见 §5.5） |
| **L2 CLI login-session 轮询 + 票据换码**（条件分支） | 窗口内展示链接/二维码 → 手机授权 → 插件轮询自动变已登录 | S–M | `POST https://mcpcn.coros.com/api/v1/cli/login-sessions` → 200 `{sessionId, pollToken, loginUrl, expiresAt, intervalSeconds:3}`（**已实测**，见 `.review-probe/session.json`）；官方 Skill `coros_mcp_login_gateway` 走的就是这条路 | ①会话寿命实测 **≈301s**；②错误 `pollToken` claim 返回 **HTTP 200 `{"status":"expired"}` 而非 4xx**——朴素 `if (!res.ok) throw` 会把过期当成功分支，界面永远转圈 |
| **L3 系统浏览器 + 本机回环回调** | 弹一次系统浏览器，授权后自动回跳插件 | M | 平台官方同款形态：`webServer.register({kind:'exact'})` + `timingSafeEqual(state)` + 302，`@deepseek-ai/dsh-deepseek-account-platform` 就是这个形状 | **违反需求 4 原文**，需需求方书面授权（§7 决策 1） |
| **L4 手动粘贴 token** | 用户在他处取 token 回插件粘贴 | S（最便宜） | `session.prompt({kind:'secret'})` 原生支持 | 体验最差；token 生命周期与安全不可控 |
| **L5 改 DSH 外壳（asar patch / 自建 BrowserWindow）** | 可真·零跳转 | XL + 持续维护债 | `dsh-tray-restart/asar-patch.js` 是既有但高风险先例 | **否决**：破坏升级，不应作为产品路径 |

### 5.3 选定策略

> **L1 为主 + L2 为条件分支 + L4 为兜底；L3 仅在 S-1 判定 L1/L2 均不可行时、由需求方签字后启用；L5 否决。**

选路判据只有一条：高驰 MCP 鉴权的实际行为，**必须在写第一行业务代码前用 S-1 spike 拿到活证据**（见 §8）。

### 5.4 一个必须提前处理的协议细节

评审中发现：`mcpcn/oauth2/authorize` 在**使用伪造 `client_id`** 探测时**无视调用方参数**，一律 302 到：

```
https://opencn.coros.com/oauth2/authorize?client_id=68mnvu3ma928t8j5s0ceb0vyinsz66fk
  &redirect_uri=https://mcpcn.coros.com/api/v1/coros/callback&scope=userInfo,runData
```

**该观测不可外推**——用 DCR（`POST https://mcpcn.coros.com/connect/register`，空 body 返回 RFC7591 风格 `invalid_request`，说明端点存在）注册出的**真实 client** 是否被同等改写，是 S-1 要回答的第二个问题。若被改写，L1 的授权码路径作废，直接转 L2。

### 5.5 信任设计（必须项，非加分项）

用户要在 DSH 窗口内把高驰账号密码输入一张第三方页面，而该页面上就写着「获取您的运动数据，其中【运动轨迹】属于个人敏感信息」。若不在其上方交代来源，用户会判定为钓鱼，闭环完成率直接崩塌。

**必须做到**：
1. iframe 上方固定显示真实域名 `opencn.coros.com`，且视觉上不可被 iframe 内容遮挡或伪造。
2. 一句明确承诺：「密码只提交给高驰官方页面，本插件不读取、不存储。」
3. 授权页加载失败时，明确提示「未能加载高驰登录页」并提供 L2 备选入口，而不是空白框。

### 5.6 登录状态机（UI 必须显式渲染）

```
未登录(anonymous)
   └─ 点击登录 → 登录中(pending) ──┬─ 授权成功 → 换取令牌 → 已连接(connected)
                                  ├─ 用户取消/关闭 → 未登录
                                  ├─ 密码错误 → 登录失败(failed, 可重试)
                                  ├─ 会话超时(expired, L2 301s) → 可重新开始
                                  └─ 网络/服务端错误 → 失败(区分原因)

已连接(connected)
   ├─ 令牌有效 → 正常展示
   ├─ 令牌临近过期 → 静默刷新(single-flight)
   └─ 刷新失败 → 需重新登录(reauth_required) + 中文重登引导
```

**五态必须可区分渲染**：`pending | authorized | failed | expired | claimed`（L2 服务器返回的 `status` 字段即这五值）。

### 5.7 平台限制（必须写进文案与验收口径）

以下来自 `@deepseek-ai/dsh-authorization` README 原文，不可绕过，只能如实告知：

| 限制 | 产品含义 |
|---|---|
| **flow 不可恢复**：一次尝试只存活于发起它的进程，登录途中刷新页面会丢弃它 | 需「请勿刷新页面」提示 + 一键重试；不能承诺恢复 |
| **没有吊销**：登出即 `deleteRecord`，只忘本地记录、不通知签发方 | 文案不得写「已断开高驰账号授权」 |
| **每凭据同时只允许一次尝试**（`ALREADY_IN_FLIGHT`） | 连点两次「登录」必须友好处理，不能抛错码 |
| **flow 返回前未提交即 `NOT_COMMITTED`** | 完成授权后若用户已关闭面板，需能被后续进入重新接上 |

### 11.3 需求 4 的达成定义（待决策 1 定稿后确认）

当前拟定为：

> **用户从点「登录」到看到设备列表，全程停留在 DSH 应用窗口内，不出现外部浏览器窗口或系统弹窗，且无需手工复制粘贴任何内容。**

若决策 1 选择接受 L3，则改写为：

> **用户从点「登录」到看到设备列表，期间允许弹出一个系统浏览器窗口用于高驰授权；授权完成后插件自动回到已登录态，无需手工复制粘贴或手动关窗回切。**
